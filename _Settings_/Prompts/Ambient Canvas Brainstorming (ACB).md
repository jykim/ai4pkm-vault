앰비언트모드로 녹취된 사용자의 생각을 실시간으로 시각화. 주제를 추출하고, 카테고리별로 분류하여 캔버스에 시각화. 캔버스가 없으면 새로 생성하고, 캔버스가 존재하는 경우 여기에 신규 내용을 반영. 업데이트는 필요시에만 진행하고, 업데이트시 기존 캔버스 내용 및 레이아웃과의 일관성을 최대한 고려.

## Input
- Transcript: 타임스탬프가 포함된 녹취 텍스트
- Existing Canvas JSON: 기존 캔버스

## Output
- Obsidian Canvas JSON (nodes, edges, metadata 포함)

## Process
### Phase 1: 콘텐츠 분석

```
1. ANALYZE TRANSCRIPT
   - 전달받은 transcript 분석
   - 타임스탬프별 발화 추출

2. EXTRACT TOPICS
   FOR EACH timestamped utterance:
     - 핵심 주제/요청 식별
     - 관련 카테고리 분류
     - 우선순위/중요도 판단

3. CATEGORIZE TOPICS
   자동 카테고리 예시:
   - 🛠️ 도구/개발: 기술, 코딩, 도구 관련
   - 📋 프로젝트/일: 업무, 할일, 프로젝트 관련
   - 💑 관계: 가족, 인간관계, 감정 관련
   - 💡 아이디어: 새로운 생각, 브레인스토밍
   - 📚 학습: 배움, 리서치 관련
```

### Phase 2: 캔버스 레이아웃 생성

```
1. LAYOUT PRINCIPLES
   - 카테고리를 중심 주변에 겹치지 않게 배치
   - 카테고리는 큰 컨테이너 박스로 (530-640px 너비)
   - 박스 높이 850px 이하 (한눈에 보이도록)
   - 카테고리 내 2열 레이아웃 기본 적용
   - 관련 노드 간 가로 연결로 높이 줄이기

2. 기본 좌표 (카테고리 배치 기준)

   카테고리 A (좌측):
   - 컨테이너: x: -750, y: -400, 530x850
   - 좌측 열 노드: x: -710 (컨테이너+40)
   - 우측 열 노드: x: -460 (컨테이너+290)

   카테고리 B (우상단):
   - 컨테이너: x: 200, y: -500, 640x650
   - 좌측 열 노드: x: 240 (컨테이너+40)
   - 우측 열 노드: x: 520 (컨테이너+320)

   카테고리 C (우하단):
   - 컨테이너: x: 200, y: 200, 640x540
   - 좌측 열 노드: x: 240
   - 우측 열 노드: x: 520
   - 전체 너비 노드: x: 240, width: 540

   카테고리가 3개 초과일 경우 위 좌표를 기준으로 확장 배치

3. CATEGORY BOX STRUCTURE
   - 카테고리 내 토픽들을 박스 안에 2열 배치
   - 좌측 열: 컨테이너 x + 40
   - 우측 열: 컨테이너 x + 290~320
   - 전체 너비 노드: 하단에 480-540px 너비로 배치
   - 열 간격: ~250-280px

4. NODE DIMENSIONS
   - 표준 토픽: 220-260px 너비, 140-180px 높이
   - 전체 너비 노드: 480-540px 너비
   - 높이 기준: 렌더링된 마크다운 1줄당 ~40px

5. EDGE 규칙
   - 관련 노드 간 반드시 edge를 생성할 것 — 텍스트 내 → 화살표를 edge 대신 사용하지 않기
   - Edge 포맷: {"id":"edge-{from}-{to}","fromNode":"{nodeId}","toNode":"{nodeId}","fromSide":"right","toSide":"left"}
   - 같은 행의 노드끼리 가로 연결 (fromSide: right, toSide: left)
   - 통찰 노드를 관련 토픽에 연결
   - 액션 노드를 관련 토픽이나 통찰에 연결
   - 다른 그룹 간 cross-connection 적극 활용
   - 가로 연결로 박스 높이 압축
```

### Phase 3: 캔버스 업데이트

```
1. GENERATE CANVAS JSON
   {
     "nodes": [...],
     "edges": [...],
     "metadata": {
       "version": "1.0-1.0"
     }
   }

2. NODE TYPES
   - cat-*: group 타입, 카테고리 컨테이너 박스
   - topic-*: text 타입, 개별 주제 노드
   - insight-*: text 타입, 통찰/결론 노드
   - action-*: text 타입, 액션 아이템 노드

3. COLOR SCHEME
   | Color | ID | 용도 |
   |-------|-----|------|
   | Red | 1 | 핵심/우선순위 높음 |
   | Orange | 2 | 관계/감정 |
   | Yellow | 3 | 진행중/프로젝트 |
   | Purple | 4 | 참조/연결 문서 |
   | Green | 5 | 통찰/인사이트 |
   | Cyan | 6 | PKM/메타 |

4. 노드 ID 규칙 (증분 업데이트의 핵심)
   - ID는 안정적이고 결정론적이어야 함: 토픽의 핵심 개념에서 파생 (표현 변화에 무관)
   - 포맷: "topic-{개념}" (예: "topic-budget", "topic-family-conflict")
   - 기존 캔버스의 노드 ID를 절대 변경하지 않음
   - 기존 캔버스가 있으면 반드시 해당 ID를 그대로 재사용
   - 기존 캔버스에 없는 새로운 토픽에 대해서만 새 ID 생성

5. PRESERVE & UPDATE MODE (기존 캔버스 JSON이 제공되는 경우)
   - 기존 캔버스 JSON이 user message에 포함되어 전달됩니다
   - 기존 노드를 그대로 복사 (id, text, color, x, y, width, height 동일하게 유지)
   - 기존 노드의 텍스트를 재작성, 번역, 의역하지 마세요
   - 기존 노드의 텍스트는 transcript에 해당 토픽에 대한 새 정보가 있을 때만 수정 (새 bullet 추가, 기존 내용 유지)
   - 기존 토픽에 없는 새로운 주제만 새 노드로 추가
   - 기존 edge 전부 보존, 새 연결만 추가
   - 기존 캔버스와 동일한 언어 유지 — 언어를 전환하지 마세요
   - 업데이트가 필요 없으면 기존 캔버스를 그대로 반환
```

## Node Templates

```json
  "id": "topic-family-cooperation",
  "type": "text",
  "text": "### 가족 협력의 어려움\n\n\"내가 뭘 하려면 아내가 도와줘야 되는데 쉽지가 않네\"\n\n- 공동 목표 설정 필요\n- 작은 것보다 큰 그림에서 서포트",

  "width": 230, "height": 160,
  "color": "2"
}
```

## Best Practices

### 컴팩트 레이아웃 유지
- 카테고리 박스 높이 850px 이하 권장
- 한눈에 전체가 보여야 함
- 너무 길어지면 2열 적용

### 적극적 중복 제거
- 비슷한 내용은 적극적으로 통합 (유사 토픽 → 하나의 노드로 병합)
- 불필요한 노드 삭제
- 핵심만 유지

### 가로 연결 적극 활용
- 세로로만 나열하지 말고
- 관련 노드 간 가로 연결 추가
- 세로 길이 줄이는 효과

## Caveats
### Skip Conditions
- 의미없는 발화만 있는 경우 (감탄사, 외국어 테스트 등) → 빈 캔버스 반환: `{"nodes":[],"edges":[],"metadata":{"version":"1.0-1.0"}}`
- 기존 캔버스가 제공되었고 새 정보가 없는 경우 → 기존 캔버스를 그대로 반환

### 언어 처리
- 모든 콘텐츠(제목, 요약, 목록)를 트랜스크립트와 동일한 언어로 작성
- 영어로 번역하지 않기 — 한국어 트랜스크립트면 한국어로 출력
- 영어 원문 인용은 그대로 유지

### 파일 크기
- 대용량 녹취는 최신 발화 우선 처리
- 오래된 발화는 요약/통합
